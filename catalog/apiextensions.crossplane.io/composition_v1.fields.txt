spec.deletionPolicy <string> enum=Background|Foreground|Pipeline	# DeletionPolicy determines how this Composition handles the deletion of its composite resources. "Background" is Crossplane's default behavior, used when this field is unset. It stops managing the composite resource as soon as it's deleted, and Kubernetes deletes its composed resources once it's gone. "Foreground" deletes the composed resources and keeps the composite resource until they're gone. "Pipeline" is like "Foreground", but keeps running the function pipeline, which decides when each composed resource may be deleted. The pipeline must eventually stop desiring every composed resource, or the composite resource will never finish deleting. Crossplane ignores this field for legacy cluster scoped composite resources, which always use "Background". This is an alpha field. It's ignored unless Crossplane runs with the --enable-function-controlled-deletion flag.

spec.pipeline[].credentials[].resolvePolicy <string> enum=Required|Optional default="Required"	# ResolvePolicy specifies how to handle missing credentials. When set to "Optional", if the referenced secret does not exist, the function will be called without these credentials rather than failing the pipeline step. When set to "Required" or unspecified, missing credentials will cause the pipeline step to fail with an error. Note that only "not found" errors are handled gracefully when ResolvePolicy is "Optional". Permission errors (forbidden, unauthorized) will still cause the pipeline step to fail regardless of this setting. Similarly, if the secret exists but the referenced key is missing, the pipeline step will fail. When an optional secret is not found, an informational event is recorded on the composite resource, but reconciliation continues normally.
