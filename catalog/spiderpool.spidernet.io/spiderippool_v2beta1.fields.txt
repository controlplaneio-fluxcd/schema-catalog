status.ipMetaData <object>	# IPMetaData carries per-IP link-layer/pairing metadata written by an external IaaS provider controller for prewarm-managed pools. It is provider-owned: Spiderpool consumes it read-only and never writes to it. For a paired (dual-stack) pool set, this field exists only on the primary pool (by convention the v4 pool); the sibling pool's own ipMetaData is left empty by the provider. Presence of an address as a key in Metadata IS the ready state; prewarm failure is expressed purely as absence from Metadata (counted in UnreadyIPCount), with per-IP failure detail in provider logs only.
status.ipMetaData.metadata <string>	# Metadata is a JSON-encoded map from a prewarmed address to its link-layer/pairing metadata. The key is the primary-family address: IPv4 for v4/primary pools, and IPv6 only for a pure-v6 single-stack pool. Presence of a key in the decoded map IS the ready state. The legacy reserved top-level key "parentNic" (the pool-level parent NIC name) is tolerated and ignored by readers; the parent NIC now lives in the structured status.parentNic field instead.

status.parentNic <object>	# ParentNic is the guest-OS parent NIC of an IaaS-managed node-level (prewarm) pool, written by the spiderpool-agent running on the pool's node (spec.nodeName): the agent copies the NIC name from the pool annotation ipam.spidernet.io/parent-nic and resolves its MAC address locally via netlink.
