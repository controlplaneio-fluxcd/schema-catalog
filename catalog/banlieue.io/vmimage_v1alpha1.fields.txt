spec <object> (required)	# VMImage — a cluster-scoped, backend-agnostic catalog entry for a bootable guest image. A VMImage names an operating system (family / distribution / version / architecture) once, then lists — per provider class — where that image actually lives on each backend (`spec.sources`). A VirtualMachine references a VMImage by name (`spec.imageRef`); the scheduler and the chosen provider resolve it to a concrete template / backing file / import URL at provisioning time. # Why create one - **One name, many backends.** "ubuntu-22.04" can map to a vSphere template, a Proxmox template VMID, and a libvirt qcow2 — users reference a single VMImage regardless of where the VM lands. - **Explicit, auditable image sourcing.** Sources (and optional checksums) are declared, not auto-discovered, so what actually boots is reviewable. - **Readiness gating.** The image controller records per-Provider readiness in `status`; the scheduler refuses to place a VM until the image is confirmed available (or importable) on a candidate Provider. Cluster-scoped: a VMImage is shared by VirtualMachines in any namespace.
spec.architecture <string> (required) enum=amd64|arm64	# Guest CPU architecture. Failure domains whose hosts cannot run this architecture are filtered out by the scheduler.
spec.cloudConfigs <[]object>	# Layered cloud-configs baked into the built artifact for `Url`-kind sources (ADR-0037). `banlieue-imagebuilder` fetches each referenced Secret in list order, deep-merges their YAML content (maps deep-merge, lists concatenate, type-mismatch errors), SSA-applies a single merged Secret (`<vmimage-name>-cloud-config-merged`), and passes *that* to the kairos-operator `OSArtifact` as `cloudConfigRef` (`auroraboot build-iso --cloud-config`). Empty list = no cloud-config. Index 0 is the base; each subsequent entry layers on top. SecretRef-first; see `CloudConfigSource` and ADR-0020. Ignored for non-`Url` sources.
spec.cloudConfigs[].secretRef <object>	# Key in a Secret in the imagebuild namespace holding the cloud-config YAML (key defaults to `DEFAULT_CLOUD_CONFIG_KEY`).

spec.cloudConfigs[].secretRef.name <string> (required)	# Name of the ConfigMap / Secret in the referrer's namespace.
spec.firstBootSealing <object>	# Declares that every clone of this image seals the listed partitions to its own vTPM on its first boot (ADR-0088), which is what lets a `VMClass` with `tpmEnabled: true` use an `Immediate` (pre-installed) image. Without it that pairing is refused, because the template was installed before any per-VM vTPM existed (ADR-0048). For a `Url` source `banlieue-imagebuilder` writes the sealing policy into the built image itself (`status.firstBootSealing: Built`); for a `Template` or `BackingFile` source the image must already carry it, and this field is an operator assertion (`Asserted`). Either way every clone's `GuestReady` waits for the guest to report each listed partition sealed. Needs a source image on Kairos v4.4.0 or later. Honoured unless `banlieue-controller` runs with `--enable-first-boot-sealing=false`, which refuses a `VirtualMachine` of this image (`FirstBootSealingDisabled`). Not combinable with `trustedBoot`.
spec.firstBootSealing.partitions <[]string> default=["COS_PERSISTENT"] min=1	# Kairos partition labels to seal on first boot. Defaults to `[COS_PERSISTENT]`. `COS_OEM`, `COS_STATE`, `COS_RECOVERY` and `COS_GRUB` are refused at admission, mirroring Kairos's own refusal.
spec.firstBootSealing.timeoutSeconds <integer> default=600 min=60 max=86400	# Seconds from the machine's power-on (its infrastructure `Ready` transition) within which the guest must report every listed partition sealed; after that `GuestReady` is `False` with reason `FirstBootSealingTimeout`. A clone that cannot seal halts in its initramfs and never reports anything, so this is how it is noticed.

spec.prelay <object>	# Pre-lay the built image (ADR-0113): `banlieue-imagebuilder` boots the raw `cloudImage` once, at build time, through the Kairos recovery reset every clone would otherwise run on its first boot, so each clone boots straight into the installed system. Only for a `Url` source built as a `cloudImage`; an `iso` build is refused (`PrelayNeedsCloudImage`). The pre-lay Job runs the published `banlieue-prelay` image (`banlieue-imagebuilder --prelay-image`) and needs `/dev/kvm` on the build node. The published artifact is the pre-laid file, with a checksum the builder computed after verifying the built file against the source's `checksum`.
spec.prelay.diskSizeGiB <integer> (required) min=10 max=65536	# The clones' OS disk size, in GiB. `COS_PERSISTENT` fills a disk of this size and does not grow on a larger one, and a smaller one cannot hold the image: give the classes that use this image this disk size (ADR-0113 Decision 4).
spec.sources <[]object> (required)	# Per-provider source mappings — one backend binding for this catalog entry per `providerClass` you intend to schedule VMs onto ("one name, many backends", see the type-level doc comment above). `x-kubernetes-list-type: map` keyed on `providerClass`: the API server rejects a second entry for a `providerClass` that already has one, rather than leaving it to `find_url_source` / `find_vsphere_source` to silently pick whichever came first.
spec.sources[].checksum <string>	# Optional checksum for imported images. Format: `<alg>:<hex>`, e.g. `sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b...`. Supported algorithms: `sha256`, `sha512`. For a `Url` source, `banlieue-imagebuilder` verifies the built artifact against this value once the build finishes and fails the build closed on mismatch or an unsupported algorithm (ADR-0010, amendment 2026-11-26); it is optional because the build measures the artifact itself.
spec.sources[].importFrom <string>	# Optional source URL. When set, providers that support image import will pull from here if the image isn't already present locally.
spec.sources[].kind <string> (required) enum=Template|BackingFile|Url|OciArtifact	# What kind of backend artifact `ref` refers to.

spec.template.rootFolder <string>	# Root vCenter inventory folder (path under the datacenter's VM folder, e.g. `templates/kairos`); created if missing.
