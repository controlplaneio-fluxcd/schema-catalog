spec <object> (required)	# VirtualMachineClaim: one subject's exclusive, time-boxed hold on one pool member. # What a claim guarantees - **Bound once, ever.** The member it binds is never handed to another subject, never returned to the warm set, and never reused. Release is always destruction. - **Deleting the claim destroys the VM**, and the claim object does not disappear until it has. - **`ttlSeconds` is a hard deadline**, not a grace period. At expiry the member is deleted whether or not the consumer is finished. # What a claim is not It is not a credential channel. `spec.subject` records *who* the member is for so the binding is auditable in the API server's own audit log; it is opaque to banlieue, and a token must never be placed in it. Delivering the subject's token to the guest is the consumer's job, over its own attested channel, anchored on the bound member's EK certificate (`status.tpmEndorsementCertificates`, ADR-0045, ADR-0049). # Which pool Exactly one of `poolRef` (one named pool) or `poolSelector` (every pool in the claim's namespace whose labels match). `poolSelector: {}` matches every pool in the namespace; a claim with neither field is refused rather than read as "any pool" (ADR-0132).

Members of every matching pool are ranked as one set (Ready only, current image revision of their own pool first, then the one Ready longest, then name), and `status.poolRef` records the pool the bound member came from. `{}` matches every pool in the namespace. Exactly one of this or `poolRef` (ADR-0132).
